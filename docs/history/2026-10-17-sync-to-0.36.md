# Sync to Offline DAoC 0.36 (2026-10-17): what was done and what we learned

Read this before the next upstream sync. The procedure is in [../UPSTREAM-SYNC.md](../UPSTREAM-SYNC.md);
this is the story behind it, so the next pull isn't rediscovered from scratch.

## What was done

1. **Code:** applied `d337d18..d88b7b2` for the server folders. No conflicts. v0.36, v0.36b and v0.36c are
   the same commit (`d88b7b2`); editions differ only in release packaging. Includes the save-snapshot
   memory-leak fix (`CoreDatabase/DataObject.cs`) and the new autonomous bot logic.
2. **Modules:** `GameServer/bots` -> `src/Bots` (compiled into GameServer); `GameServer/admin` ->
   `src/Admin.Host` (own project). Only two seams to core: `AdminHost.Register()` in
   `CoreServer/Actions/ConsoleStart.cs` and `LoginRequestHandler.NewAccountPrivLevelProvider`.
3. **World:** `world/patches/200-*.sql` regenerated from the 0.36 plain-edition DB; verified 0 differing tables.
4. **Navmeshes:** set `classic-si-3`, stored one `.xz` per mesh. 103 meshes + `seams.json` were identical to
   0.35; `pockets.json` changed and `roads.json` is new (used by `AutonomousZoneRoads`).
5. **History rewritten once** to drop old navmesh archives (clone went 1.1 GB -> ~384 MB). Backup bundle of
   the old history was kept by the owner; commit SHAs before 2026-10-17 are gone.

## Things that cost time (so they don't again)

- **Release DB and navmeshes are only in the release zip.** The zip is split (`.zip.001-.003`, 4.8 GB). Don't
  download it: `tools/world/rangezip.py` reads single files with HTTP range requests (the DB is 30 MB
  compressed). Plain-edition DB path: `OfflineDAoC-v0.36b/editions/0.36-no-custom-class/runtime/data/opendaoc.sqlite3.db`;
  its SHA-256 is in the release's `download-manifest.json`. Navmeshes: `runtime/server/navmesh/`.
- **Check navmesh changes per file** (compare SHA-256 with `world/navmesh-manifest.sha256`) before assuming a
  new set. This time only 2 of 105 files changed.
- **Startup logs ~390 ERR on a healthy server.** That is the baseline, and it is upstream's own data: the
  official 0.36 DB gives the identical errors (240 `LineXSpell` rows for missing poison/potion spells, 42
  missing NPC templates, 35 door-registration, 15 null-spell templates, plus a handful). Compare counts and
  error *types* after a sync; a jump means something broke. Before 0.36 data it was 1,157 (557 quest
  reward items were missing in the 0.35 world).
- **The version shown in the TUI** is `AdminService.OfflineDaocVersion`; bump it every sync.
- **Sluaghbinder** code is woven into shared enums, so it can't be left out of a sync. It stays off
  (`classes / enable_sluaghbinder = False`).
- **Environment:** the VS Code flatpak sandbox has a small tmpfs `/tmp` (about 1.5 GB) and no distrobox;
  clone and download under `/home`, and run box commands with `flatpak-spawn --host distrobox enter ...`.
  The session scratchpad can disappear between steps. A fresh box needs ~10 minutes
  (`tools/setup-build-box.sh --build`).
- **Testing recipe:** copy `dist/daoc-server` to a test folder in the box home, `./daoc-server.sh start`
  (TUI), `./daoc-admin accounts create <name> <pw>` then `accounts set-role <name> admin`, client on 10300.
  Ask the owner before starting a server; they sometimes run one.

## Not built yet (ideas, in priority order)

1. `tools/upstream/update.sh <tag>`: one command for code, world (rangezip + derive + verify) and navmesh
   (stage) steps, then build, tests and a startup run.
2. A committed error baseline (error types and counts) that the script compares against.
3. An "our changes vs upstream" report (files where we differ from upstream at the synced sha).
4. `sync.sh apply` has only been tested with `check`/`report`; the first real `apply` may need fixes.
5. The 390 baseline errors could be fixed in a `300-*.sql` patch (triage which ones bots or players hit first).

## Addendum: 0.37 (2026-10-20) used the release's game patch

- 0.37 is the first release that ships `OfflineDAoC-v0.37-game-patch.zip` (36 MB) with `db-0.37.json` (row-level world
  delta with Old/New values) and the changed navmesh files. That replaces the range-reading and the whole-DB diff.
  `tools/upstream/update-data.sh` does it; `rangezip.py` is only needed if a release has no patch.
- First real `sync.sh apply`: one file (`AutonomousPopulationController.cs`) conflicted with our edits; the script now
  does a 3-way merge for such files. Our edits to upstream bot files are the main source of future conflicts, so keep
  new bot features in new files under `src/Bots/` where possible.
- The build box home (`~/boxes/daoc-merge-box-home`, including the .NET SDK and test folders) was wiped between sessions;
  `tools/setup-build-box.sh` restores it. Don't keep anything precious there.
